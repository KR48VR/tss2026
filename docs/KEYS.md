# API keys: what each unlocks, how to get it, and what we do without it

The pipeline reads most statistics offices without any credential. Four offices put their machine-readable tables behind a free key. A key is never pasted into the chat or the repository: it goes into the cloud environment's settings (the environment menu in the session's title bar, then Edit; under Network secrets where offered, otherwise as an environment variable) under the exact variable name below, and a new session picks it up.

| Office | Variable | What it unlocks | How to get it | Without it |
|---|---|---|---|---|
| Stats NZ (Aotearoa Data Explorer API) | `STATSNZ_API_KEY` | New Zealand from limited to medium: Census 2023 median income by occupation sub-major group (the Explorer publishes no unit-group income table) and the occupation-by-industry table, which gives the sector lens. Used in the build of 30 October 2026 | Sign up at portal.apis.stats.govt.nz/signup (email, password, first and last name, and an "I'm not a robot" check that only a person can tick, which is why this one was not done from the pipeline's side), confirm the email, then under Products subscribe to "Aotearoa Data Explorer" and copy the subscription key | The 2023 Census employment by unit group and the HLFS median earnings by major group, downloaded from figure.nz and Stats NZ's file releases (the current record) |
| Destatis (GENESIS-Online) | `DESTATIS_USER` and `DESTATIS_PASSWORD` | A full German record: pay by five-digit KldB occupation (earnings survey, one year per call because the table is too big for one), the ICT-use survey by section, the Microcensus by two-digit occupation; the employees by occupation come from the Federal Employment Agency's open spreadsheets. Used in the build of 30 October 2026 | Register a free account at genesis.destatis.de (email, password, two consent boxes, a confirmation email). The loader sends no key: Melodi answers 401 when the portal's application key is sent as the integration header, and answers everything the record needs without one | Not needed for the data: Melodi (api.insee.fr/melodi, the catalogue and data endpoints) answers without any key at 30 calls a minute, tested 30 October 2026 from the pipeline's environment. ## Where the credentials made on 30 October 2026 are kept

The German account's password and the French application's key were generated by the pipeline's session and written to a file in that session's scratchpad (`keys/credentials.json`), never into the chat or this repository. The project owner copies them into the environment settings under the variable names above, and may change the passwords on each site at any time (both sites offer "change password" on the account page). The accounts use the owner's own email address.

## KOSIS: why there is no key, and what the download route costs

**What the key needs.** KOSIS membership runs through the Korean government's ONE-ID identity check, which offers two routes only: a mobile phone registered in the person's own name with a Korean carrier, or an I-PIN, which needs a Korean resident registration number. There is no email or foreigner route, and the FAQ says the open-data service uses the same membership as the portal. The Ministry of Data and Statistics confirmed this in writing on the KOSIS English board on 8 October 2026 (answer to "Queries related to OPEN API from KOSIS"): membership is for individuals only, not companies, and requires authentication through a domestic mobile provider. So the key is only possible for someone with a Korean phone number in their own name. If that ever becomes available, the steps are: sign up at kosis.kr through the phone check, open kosis.kr/openapi, press "OPEN API 인증키 신청" (request a key), and store the key as `KOSIS_API_KEY`.

**What we do instead.** Every KOSIS table can be downloaded from its web page without an account (the download panel on the table page offers CSV, Excel, TXT and SDMX; tested 30 October 2026). The Korea record is built from those downloads, driven by a headless browser in `fetch.py`, so the numbers are the same ones the API would return.

**The drawbacks of the download route, so nobody is surprised later.**
1. *Fragility.* The fetch works the website's own download form. A redesign of the site can break it; the API would not break the same way.
2. *Size.* A download covers the items selected on screen. The largest tables (every occupation by every industry) must be selected in full or pulled through the site's separate large-download step, sometimes in pieces.
3. *Shape.* The downloads are CSV or Excel with Korean labels; the API returns JSON with codes and English labels where they exist. The loaders carry their own code lists and English titles.
4. *Refresh.* The API would make Korea as easy to keep current as the European records. The download route still refreshes on `python -m onetx fetch`, but needs a check after each KOSIS release that the form has not moved.

**Swapping the key in later.** The loaders read the same tables either way. With a key, `fetch_kosis_table` can call the API endpoint instead of the web form, and nothing else in the record changes.
